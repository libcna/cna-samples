# SAMPLE-004 audit — `StockEffectsSample_4_0`

Status: Content Pipeline tool port complete (`✅`). The project owner changed the former non-port
decision on 2026-09-12 and selected a deliberately narrower product boundary: port the original
`CompileEffect` command-line tool, but do not invent a native game or browser demo for a package
that has neither.

## Classification and selected boundary

The upstream package is not a `Game`. Its runnable product is `CompileEffect`, a command-line
authoring tool that calls `EffectImporter` and `EffectProcessor` and writes raw compiled effect
bytes. The sibling `StockEffects` project is an educational copy of the six XNA stock-effect
wrappers, not another executable.

The selected CNA port therefore contains:

- the original four-file `CompileEffect` flow translated to C++;
- the XNA-shaped importer and processor calls, custom contexts, warning-as-error logger, argument
  validation and raw `.bin` output;
- one host-tool CMake target, `CompileEffect_cna_samples` (output name `CompileEffect`).

It intentionally contains no native game target and no Emscripten target. The wrapper library is
not aliased to CNA's built-in effects; doing that would not port its source and would obscure the
owner-selected boundary. The exact C++ translation mechanics are recorded in `diff.md`.

## Framework defects fixed while porting

The faithful tool exposed two CNA defects, both fixed in `../cna` rather than bypassed here:

1. `EffectCompilerService` derived sampler masks only from shader bytecode stored directly in a
   pass. XNA stock effects select permutations from global shader arrays, whose shader objects live
   in the small-object table. CNA now resolves the selected array, reads every possible shader
   object and attributes its sampler bindings to that pass. The six produced masks are now exactly
   the XNA values: `1, 1, 3, 3, 1, 1` for AlphaTest, Basic, DualTexture, EnvironmentMap, Skinned and
   Sprite respectively.
2. `DirectionalLight` only cached values. Its XNA/FNA parameter-bound constructor and setter
   synchronization are now implemented and tested, including clone construction and enable/disable
   color propagation.

`EffectProcessor` also now resolves quoted includes beside the original `EffectContent` identity,
as XNA does, while retaining its temporary compiler input.

- `xna4-original/StockEffects`: exact upstream source snapshot;
- `xna4-build/CompileEffect/CompileEffect.exe`: unchanged original tool;

- `cna-content-pipeline`: reproducible CMake build tree, removable after an owner-approved prune;
- `evidence`: retained build and comparison logs.

The release port built against sibling `../cna` and `../sharp-runtime`, with only `StockEffects`
configured. It compiled all six original `.fx` files through the local June 2010 `fxc.exe` and
their original `.fxh` includes. For every pair, byte length and container header match XNA:

| effect | bytes | header words |
|---|---:|---|
| AlphaTestEffect | 5,608 | `bcf00bcf 00000010 00000000 00000001` |
| BasicEffect | 28,840 | `bcf00bcf 00000010 00000000 00000001` |
| DualTextureEffect | 4,696 | `bcf00bcf 00000010 00000000 00000003` |
| EnvironmentMapEffect | 10,984 | `bcf00bcf 00000010 00000000 00000003` |
| SkinnedEffect | 55,548 | `bcf00bcf 00000010 00000000 00000001` |
| SpriteEffect | 1,120 | `bcf00bcf 00000010 00000000 00000001` |

The full blobs are not claimed byte-identical: Microsoft's retained XNA build embeds HLSL compiler
9.26 output, while the locally available DirectX SDK compiler is 9.29. That expected compiler
difference does not alter the verified lengths, container structure or corrected sampler masks.
